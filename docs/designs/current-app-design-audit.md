# LEFT30 현재 앱 디자인 기준 및 기존 문서 대조

작성: 2026-11-16. 기준: 이 저장소의 React Native 화면 코드 정적 조사. 실기기 캡처와 사용성 검증은 아직 하지 않았으므로 픽셀 배치와 실제 조작감은 확정하지 않는다.

> 2026-11-16: 여기서 말하는 `left30-cat.md`와 수채화 원칙은 `left30-visual.md`로 합쳐졌다. `docs/designs/cat/` 그림 원본은 design/cat-image 브랜치에만 있다.

## 1. 현재 화면 구조

| 화면 | 현재 보이는 핵심 요소 | 주요 조작 | 코드 |
|---|---|---|---|
| 로그인 | 검은 배경, 로고, 카카오 로그인, 실패 문구 | 카카오 로그인 | `application/app/(login)/index.tsx` |
| 온보딩 | 방해금지 시간, 알림 권한 및 정확한 알림 설정 | 시간 설정, 권한 허용 또는 나중에 | `application/app/(onboarding)/index.tsx` |
| Todo | 날짜, 카테고리별 목표 한 줄, 06–24 계획 막대, 계획 블록 목록 | 목표 설정, 어제 가져오기, 블록 추가·수정·체크·밀어서 삭제 | `application/components/todo/TodoScreen.tsx` |
| Home | 가로 전환 버튼, 큰 30분 카운트다운, 집중 상태 및 조작, 계획 대비 실제 | 집중 시작·종료·연장, 총량 계획 설정 | `application/app/(tabs)/index.tsx`, `application/components/focus/FocusStatus.tsx`, `application/components/home/PlanVsActual.tsx` |
| Timetable | 어제·오늘 두 열, 30분 칸, 1시간 가로줄, 현재 시각선 | 지난 칸 탭해 기록 | `application/components/timetable/Timetable.tsx` |
| 계정 관리 | 카카오 연결, 방해금지 시간, 탈퇴 | 각 설정·확인 모달 | `application/app/(user)/index.tsx` |

탭 순서는 `Todo | Home | Timetable`이다. 상단 헤더와 하단 탭은 검정 바탕, 밝은 글자와 아이콘을 쓴다. 기록 시트는 루트에 놓여 알림이나 시간표에서 열 수 있다. Home 가로 모드에서는 계획 대비 실제를 숨긴다.

## 2. 현재 시각 언어와 상호작용 규칙

- 바탕은 대체로 `black`; 시트는 `GRAY_9`(`#212529`), 주요 글자는 `GRAY_0/1`, 보조 글자는 `GRAY_5/6`이다. `application/assets/palette.tsx`에 회색 단계와 `calm_summer` 색 6개가 있다.
- 카테고리 색은 업무 `#0d4c89`, 휴식 `#6090b9`, 관계 `#dfdbd2`, 운동 `#c99f75`, 자기개발 `#9a918b`, 수면 `#887972` 순으로 매핑한다. 기록 시트의 선택 순서는 별도로 수면·휴식·운동·관계·자기개발·업무다. 단일 출처는 `application/record/categoryStyle.ts`다.
- Home 타이머는 110sp, 블록 상태는 15sp, 일반 조작은 16sp 안팎이다. Todo 날짜는 18sp, 블록은 15–16sp, 시간표 눈금·칸 글자는 13sp다. 명시적인 전역 타이포그래피 토큰이나 글꼴 체계는 없다.
- Todo 블록: 동그라미는 끝난 블록 체크, 본문은 수정, 왼쪽 스와이프는 지우기다. 체크와 삭제 뒤 3초 토스트에서 되돌릴 수 있다. 기존 기록과 겹쳐 체크하면 덮어쓰기와 빈 칸만 채우기 중 고른다.
- Timetable 오늘 열에는 계획을 카테고리 색의 약 30% 불투명도로, 실제 기록은 진하게 그린다. 어제 열은 실제 기록만 표시한다. 각 30분 칸은 28dp이고 끝난 칸만 기록 시트를 연다.
- Home 계획 대비 실제도 같은 카테고리 색을 쓴다. 목표는 약 30% 불투명도, 실제는 진한 막대다. 목표나 실제 기록이 있는 카테고리만 노출한다.

### 제안: 색을 줄인 다음 디자인 기준

이 절은 **현재 구현이 아니라 변경 방향**이다. 카테고리 6색은 데이터와 UI에 남아 있지만, 다음 시안에서는 색으로 카테고리를 암기하게 하지 않는다.

| 역할 | 제안 색 | 사용 |
|---|---|---|
| 기본 바탕 | `#000000` | Home, Todo, Timetable 배경 |
| 표면 | `#212529` | 시트, 토스트, 선택 영역 |
| 주 글자 | `#f8f9fa` | 제목, 숫자, 행동 |
| 보조 글자·선 | `#adb5bd` / `#495057` | 설명·눈금 / 구획선 |
| 유일한 UI 강조색 | `#6090b9` | 선택, 기록된 시간, 진행 상태 |

카테고리는 색 대신 **이름을 우선 표시**한다. Todo 목록은 범주명과 제목, 시간표는 블록 시작점의 범주명과 블록 경계, Home 비교 막대는 범주명과 숫자로 구별한다. 계획은 강조색의 옅은 채움 또는 윤곽, 실제는 진한 채움으로 구별하되 `계획`/`실제` 텍스트와 접근성 라벨도 제공한다. 연속된 서로 다른 범주의 블록은 색이 같더라도 간격·구분선·반복 라벨로 구분해야 한다. 경고·삭제는 별도 상시 색을 추가하지 않고 문구와 확인 동작으로 표현한다.

고양이의 털색은 **선택한 품종의 자산에만 속한다**. Calico의 주황·검정·흰색을 앱의 버튼, 범주, 가구 기본색으로 가져오지 않는다. 흰색·검정·회색·갈색 등 다른 품종도 같은 중립 배경에서 읽히는지 시안으로 검증한다. 고양이 뒤에는 필요할 때만 일정한 중립 대비층을 두고, 품종마다 화면 전체 테마를 바꾸지 않는다. 이 기준이라면 고양이 자체가 화면의 유일한 다색 요소가 될 수 있다.

## 3. 기존 Claude 문서와 비교

| 기존 문서의 내용 | 현재 코드에서 확인한 상태 | 판정 |
|---|---|---|
| `left30-focus-block.md` DR-2: 영어 탭 `Todo | Home | Timetable` | 탭 레이아웃과 일치 | 일치 |
| DR-1 수정: 큰 타이머를 유지하고 아래에 집중 상태·끝내기·30분 더 | `FocusStatus`에서 일치 | 일치 |
| DR-3·4·6·9: Todo 목록·목표·체크, 시간표의 옅은 계획 레이어 | 모두 화면 코드에 존재 | 구현 반영 |
| D6 메모: Home 계획 대비 실제 영역이 아직 없음 | `PlanVsActual`이 Home에 렌더링됨. 목표/실제 막대와 빈 상태도 존재 | **문서 상태가 낡음** |
| `left30-cat.md`: 고양이를 Home·기타 탭에 배치하는 단계별 제안 | 현재 화면·컴포넌트에 `CatStage`가 없고 `docs/designs/cat/`의 그림은 앱 자산으로 연결되지 않음 | **제안 단계**, 현재 디자인으로 기재하면 안 됨 |
| 고양이 문서의 카테고리 6색 조화 기준 | 품종 확장과 화면 단순화 방향에 맞춰 위 단일 강조색 기준으로 수정 | **이번 결정 반영** |
| 재출시 문서의 광범위한 제품·데이터·실험 계약 | 실행 화면의 시각 규칙과 상태를 찾기 어려움 | 이 문서가 현재 UI 인덱스를 보완 |

기존 문서는 결정과 구현 기록을 섞어 보관한다. 결정 자체는 지우지 말고, 완료/미완료 표시를 실제 코드와 주기적으로 맞춰야 한다. 특히 `left30-focus-block.md` D6의 완료 조건을 다시 검토할 필요가 있다. 이 정적 조사만으로 기록 집계 로직이 DR-5와 완전히 일치하는지는 판정하지 않았다.

## 4. 추가할 디자인 결정과 의심 지점

1. **Home 세로 공간:** 110sp 타이머, 집중 상태, 여러 개의 계획 대비 실제 막대가 세로 중앙에 함께 놓인다. 작은 화면·큰 글자 설정에서 잘림이나 탭바와의 충돌을 실기기로 확인하고, 스크롤/축소 우선순위를 정한다.
2. **가로 모드의 정보 손실:** Home만 가로 전환하며 계획 대비 실제가 사라진다. 의도한 집중 모드인지, 회전 뒤에도 계획 요약에 접근할 수 있어야 하는지 결정한다. 현재 `가로로 전환` 글자는 10sp로 다른 조작보다 작다.
3. **상태의 표현:** 현재는 색상만으로 카테고리를 구분하는 막대가 있다. 제안한 단일 강조색으로 바꿀 때는 모든 블록의 범주명과 경계를 읽을 수 있게 해야 한다. 계획/실제 차이도 투명도만으로 전달하지 말고 범례와 텍스트를 검증한다.
4. **로딩·오류·빈 상태:** Home 계획 대비 실제는 로딩 중 `null`, Timetable은 빈 검은 화면이다. 데이터가 느리거나 읽기 실패할 때 사용자에게 보일 상태와 재시도 행동을 문서화한다. Todo는 빈 상태와 저장 실패 토스트가 이미 있다.
5. **텍스트와 터치의 일관성:** Todo는 체크·수정·스와이프 동작이 한 행에 공존한다. 최초 사용자에게 조작을 알려 주는 방식, 실수 방지, 스크린리더 동선과 1.3배 이상 글자 확대 동작을 실기기로 확인한다.
6. **디자인 토큰 정리:** 위 5개 역할을 공통 토큰으로 만든 뒤 화면별 상수를 줄인다. 시트 모서리, 44–52dp 터치 높이, 글자 크기도 함께 정리한다. 카카오 로그인 노란색은 외부 서비스 자산 예외로 별도 취급한다.
7. **고양이 범위:** 그림 파일이 많아도 앱에 연결된 고양이 UI는 아직 없다. Calico 외 품종을 지원할 공통 배경·크기·실루엣 기준을 먼저 정한다. `left30-cat.md`의 보상·가구는 후속 단계로 유지한다.

## 5. 다음 검증

Android 작은 화면과 큰 화면에서 로그인→온보딩→Todo 빈/채운 상태→Home 평소/집중 중→Timetable 기록 시트→가로 회전을 캡처한다. 기본 글자와 시스템 글자 확대, TalkBack, 긴 블록 제목, 여러 카테고리, 자정 전후를 포함한다. 이 결과를 기준으로 위 4절의 우선순위와 실제 디자인 토큰을 확정한다.
