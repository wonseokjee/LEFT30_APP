# LEFT30 화면 디자인: 고양이와 수채화

작성 2026-11-12(고양이), 2026-11-16(수채화). 2026-11-16 두 문서(`left30-cat.md`, `left30-watercolor.md`, design/cat·design/cat-image 브랜치)를 이 문서 하나로 합쳐 refactor/architecture로 옮겼다. 그 브랜치의 옛 문서는 이 문서를 가리키는 안내만 남긴다.
상태: **원칙·홈 배치·글자 색·시간표 모양 확정(2026-11-17), 글꼴 = 앱 전체 주아(2026-11-18 디자인 리뷰 3, G2~G24, 6.1). 강조색 최종값·밤 색 값·작은 글자 글꼴 미정.** 방 배경(낮·밤)과 밝은 방 가구 시안(선반·발판·스크래처·캣타워)을 받았다(design/cat-image `docs/designs/room/`). 가구는 무광, 선 굵기는 고양이에 맞춤, 가로는 범위 밖(2026-11-17 에셋 제작 규칙, 5.0). 고양이 0단계(역할과 구조) 확정, 1단계(스타일)는 수채화로 정함.
관련: 기능과 데이터 `left30-timer-modes.md`(타이머 개편, 디자인 리뷰 진행 상태와 배경 그림 요청 조건), 재출시 설계 `left30-relaunch.md`(D4 기록 1탭, D7·D12~D15 디자인 리뷰, D10 사실만 쓰기, E4 스트릭 연기), 집중 블록 `left30-focus-block.md`, 현재 화면 점검 `current-app-design-audit.md`.

**그림 원본 위치:** 고양이 그림 원본과 품종별 재생성 규칙(`cat/*.png`, `cat/*-regeneration-guide.md`)은 용량 때문에 **design/cat-image 브랜치의 `docs/designs/cat/`에만 둔다**(커밋 안 된 파일 포함). 이 브랜치에는 앱에 넣을 때 줄인 파일(`application/assets/cat/`)만 들어온다. 이 문서에서 `cat/…`는 그 위치를 뜻한다.

## 1. 목표

- 앱의 얼굴을 고양이로 바꾼다. 고양이는 Home에 늘 있고, 앱 상태에 따라 행동이 바뀐다.
- 고양이만 동화책 수채화, 바탕·UI는 단색 + 옅은 종이결, 가구는 매끈한 무광이다(P4). **홈은 고양이가 사는 방 그림이 된다**(P6).
- 나중에 모션, 가구, 화면을 계속 늘릴 수 있도록 처음부터 **데이터로 정의하고 코드는 재생만 하는 구조**로 만든다(9절).

## 2. 원칙

### 2.1 화면 (2026-11-16, 사용자)

| # | 원칙 | 근거 |
|---|---|---|
| P1 | **품종 중립.** 고양이는 삼색(calico) 외에 검정·흰색·회색·크림 등 여러 품종을 쓴다. 털색은 그 품종 그림에만 속하고, 앱의 버튼·카테고리·가구 기본색으로 가져오지 않는다. 품종마다 화면 테마를 바꾸지 않는다 | 사용자 지시 "calico만 기준으로 색을 잡으면 안 돼" |
| P2 | **색 축약.** UI는 중립색(바탕·표면·글자·선)과 강조색 하나로 만든다. 경고·삭제에도 상시 색을 더하지 않고 문구와 확인 동작으로 표현한다 | 사용자 지시 "색이 너무 많으면 복잡해 보여" |

| P5 | **행동 원칙 유지.** 카드·테두리·그림자 없음(D12), 기록 1탭(D4), 사실만 쓰기(D10), 접근성(D15). 화면 모양은 P6·P7로 새로 만든다 | 2026-11-16 "기존을 완전히 갈아 엎을거야"로 화면 구성은 새로 하고, 1탭·사실만·접근성은 바꾸라는 말이 없어 유지로 본다 |

| P7 | **검은 바탕을 버리고 밝은 바탕 + 다크 모드.** 다크 모드는 같은 방의 밤 그림이다 | 2026-11-16 사용자 "검은 배경도 아니고, 다크모드 도입할거야" |

색은 여전히 줄인다(P2). 방 그림은 고양이보다 채도·대비를 낮춰 고양이가 앞에 보이게 한다.

### 2.3 접근성 (2026-11-17, 디자인 리뷰 D19)

- 누르는 곳은 48dp 이상.
- 큰 숫자는 폰 글자 크기 설정을 1.3배까지만 따른다(화면 넘침 방지). 다른 글자는 그대로 따른다.
- 화면 읽기: 숫자는 초마다 읽지 않는다. 숫자에 붙는 말은 짧게 "1시간 23분 지남", "18분 남음"(분 단위). "집중 · 스톱워치"(세부 항목이 있으면 그 이름)는 아래 라벨이 따로 읽힌다.
- 움직임 줄이기: 앱 설정을 따로 만들지 않고 폰의 "애니메이션 제거"를 따른다(C4). 고양이 모션과 숫자 바뀜 애니메이션을 끈다.
- 상태는 흐림·색만이 아니라 글자로도 보인다(예: "일시정지 중").
- 굵게로 강조하지 않는다(G6, 6.1). 고른 칩·방식 칸·켜진 버튼은 채움으로 보이고, 화면 읽기에는 선택 상태(`accessibilityState`)를 따로 붙인다.
- 시간표의 짧은 블록은 4.3a "블록 누름"의 48dp 규칙을 따른다(G12).
- 다크 모드 색은 밤 전용 표로 정하고, 모든 밤 글자·배경 조합이 작은 글자 4.5:1, 큰 글자·누르는 곳 경계 3:1 이상이어야 한다. 벽·바닥 각각 계산한다(G10, 6절).

### 2.4 다크 모드 (2026-11-17, D15)

- 기본은 폰 설정을 따르고, 계정 관리에 "화면: 폰 설정 / 낮 / 밤" 한 줄을 둔다.

### 2.2 고양이 (2026-11-12)

- **C1 누르는 것을 막지 않는다.** 고양이는 터치를 받지 않는다(`pointerEvents='none'`). 기록 1탭, 버튼, 시간표 칸 위로 올라오지 않는다. **홈 큰 숫자는 그림으로 가려도 된다**(2026-11-18 G23, 사용자 "가려도 된다"). 숫자 위·앞을 지나는 모션을 막지 않는다. 화면 읽기는 숫자를 그대로 읽는다. **예외(나중, 2026-11-21 사용자):** 홈 선반 고양이만 탭을 받아 살짝 오른쪽으로 비켜 가린 숫자를 보여 준다(10절 nudge). 기록 1탭·버튼·시간표 칸 위에 있는 고양이는 지금처럼 터치를 받지 않는다.
- **C2 고양이는 평가하지 않는다.** 기록을 놓쳐도 슬퍼하거나 화내지 않는다. D10(사실만, 평가 없음)과 같은 원칙이다. 기록했을 때 반기는 반응은 괜찮다.
- **C3 표시는 적게.** Home 밖 화면(Todo, Timetable)에는 가끔만 나온다.
- **C4 움직임 줄이기 설정을 따른다.** OS의 "애니메이션 제거"가 켜져 있으면 정지 포즈만 보여 준다.
- **C5 배터리.** 앱이 백그라운드이거나 화면이 안 보이면 재생을 멈춘다. 반복 모션은 쉬는 간격을 둔다.

## 4. 화면별 장면

탭 순서는 `Todo | Home | Timetable`이다.

### 4.1 Home 세로

- **방이 화면 전체 배경이다(P6).** 처음 안(화면 아래쪽 또는 타이머 옆의 "방" 영역)은 버렸다.
- 타이머 숫자는 방 안의 구조물이다. **배치는 벽 선반으로 정함(2026-11-17, D22).** 숫자는 벽에 걸린 선반(`floating-shelf-light-mid-v4.svg`, 5.1) 위의 물건처럼 서고, 고양이는 선반 끝에 앉는다. 숫자 위 작은 글자 **"다음 30분 기록 알림까지"**(2026-11-18 G14, 사용자가 Codex 안을 고름. 처음 연 사람도 무슨 알림인지 알게). 바닥(바닥선 약 63% 아래)에 **[시작] 버튼 하나**(D38)와 "오늘 지금까지" 막대 두 줄(4.3c, D37). 스톱워치·뽀모도로 진행 중에는 숫자 위 같은 자리 라벨에 **"제목 · 방식"만** 보인다(예: "TOEIC RC · 스톱워치", "TOEIC RC · 뽀모도로 1/4바퀴"). "30분 알림 쉼"은 넣지 않는다(2026-11-21 사용자 "제목.뽀모도로 아까처럼 이거는 보여주고 '30분 알림 쉼' 이 문장만 보여주지 않기"), 바닥에 [일시정지] [정지]만 남는다. 나중에 고양이가 선반에서 숫자 위로 오르는 모션이 이어진다. 시안: `~/.gstack/projects/wonseokjee-LEFT30_APP/designs/home-timer-20261116/home-real-bg.html` ①.
- **큰 숫자 (2026-11-18 디자인 리뷰 3):**
  - 크기(G7): 화면 너비에 비례한다. 393dp에서 80, 360dp에서 약 73, 430dp에서 약 88, 상한 96(아이패드 등). 폰 글자 크기는 그 위에 1.3배까지(2.3). iOS도 같은 규칙(pt).
  - 숫자 칸(G4): 주아 숫자는 폭이 제각각이다(0=612, 1=411, 4=628 / 1000, 고정 폭 숫자 기능 없음, 파일 확인). 숫자 한 자리마다 가장 넓은 숫자 폭의 칸에 가운데 맞춤으로 넣고, 콜론도 고정 칸. 1초마다 숫자가 옆으로 움직이지 않는다.
  - 기준선(G5): 숫자 칸 아래 끝 = 선반 윗면 y. `includeFontPadding: false`, `lineHeight` = 글자 크기. 글자가 커지면 위로만 자란다. 위쪽 라벨·날짜 줄과의 간격은 폰에서 확인.
  - 숫자 형식(2026-11-18, 사용자 "1시간 까지는 59:59 초단위까지로 나오는데 1시간 넘어가면 1:00처럼 시간과 분단위로"): 1시간 미만은 **분:초**(`59:59`, `9:59`, `0:05`), 1시간부터는 **시:분**(`1:00`, `1:23`, `12:05`)이고 초는 보이지 않는다. 스톱워치 지난 시간, 타이머·뽀모도로 남은 시간, 다음 알림까지 모두 같은 규칙. 앞자리 0은 붙이지 않는다(분:초의 초, 시:분의 분은 두 자리). 1시간 이상에서는 숫자가 1분마다 바뀐다. `1:00`(시:분)과 `1:00`(분:초)이 같아 보이므로 화면 읽기는 늘 단위를 붙여 읽는다("1시간", "1분"). 고정 알림의 시스템 크로노미터는 안드로이드가 그리는 형식(`1:23:05`)이라 이 규칙을 따르지 않는다.
  - 정렬(2026-11-21, 사용자 "숫자는 왼쪽에 놓고, 라벨은 숫자끝과 오른쪽 끝라인을 맞춘다"): 큰 숫자는 **왼쪽 정렬**(첫 글자가 왼쪽 여백 393dp 기준 26에서 시작). 위 라벨은 **오른쪽 끝을 숫자 끝에 맞춘다.** 숫자 폭이 바뀌면(`12:41` → `1:23`) 라벨도 따라 움직인다. 숫자 칸은 같은 폭이라도 칸 안 글자 끝이 숫자마다 다르다(80 기준 칸 왼쪽에서 `1`은 33.4, `4`는 47.1, 폰트 파일 확인). 실제 글자 끝을 따라가면 라벨이 매초 0~14px 움직여 거슬린다(사용자 확인). 그래서 라벨은 **고정선**에 맞추고 움직이지 않는다. 마지막 숫자는 칸 가운데에서 오른쪽으로 **(칸 폭 − 그 숫자 폭) ÷ 4만큼만** 옮긴다(오른쪽 끝까지 붙이면 `1`일 때 `12:4 1`처럼 벌어짐). 고정선 = 마지막 칸 오른쪽 끝 − 4.1(80 기준, 글자 크기 비례). 끝 숫자가 `1`일 때만 라벨이 숫자보다 약 8px 더 나간다(2026-11-21 사용자 선택, 비교 시안 `home-jua-20261118/label-align.html`, `last-one.html` ③). 날짜는 맨 위 왼쪽. 고양이는 선반 오른쪽 끝에 앉는다. 숫자를 가려도 된다(G23), 나중에 탭하면 살짝 비킨다(2.2 C1 예외). 시안: `~/.gstack/projects/wonseokjee-LEFT30_APP/designs/home-jua-20261118/home-current.html`.
  - 고양이와 위계(G13): 숫자가 첫째. 앉은 고양이 키 ≤ 숫자 글자 높이 × 1.2. 포즈별 `scale`(9.1)로 맞추고 숫자를 따라 화면 너비에 비례한다.

### 4.3 Todo, Timetable

- 탭 바 바로 위, 화면 맨 아래의 얇은 띠(높이 약 56dp)에만 나온다. 목록과 시간표의 아래 여백을 그만큼 늘려 내용을 가리지 않게 한다.

### 4.3a 시간표 = 구간 타임라인 (2026-11-17, D26~D29)

- **블록**: 카테고리 색 없이 모두 같은 채움(낮 `#E0CCB7`, 밤 `#57504A`) + 왼쪽 3dp 강조선. 이름은 블록 위쪽. 서로 다른 기록 사이는 2dp 틈. 30분 알림 답이 같은 카테고리로 이어지면 한 덩어리로 그린다. 같은 카테고리라도 기록 출처가 다르면(알림 답 → 타이머) 따로 그린다.
- **짧은 블록**: 15분 미만은 이름 없이 블록만 그린다(D28). 누르면 시트에서 보이고, 화면 읽기는 항상 이름을 읽는다.
- **멈춤·휴식**: 5분 미만 멈춤과 뽀모도로 휴식은 블록 안에 약간 옅은 색(낮 `#E9D9C7`, 밤 `#48423E`)으로 칠한다(D13). 5분 이상 멈춤은 빈 틈으로 두고 앞뒤 조각을 점선으로 잇는다. 뒤 조각에는 이름을 반복하지 않는다(타이머 개편 PAUSE).
- **진행 중**: 지금 선까지 자라고 아래 끝이 흐려진다. 이름 뒤에 "진행 중".

- **계획**: 기록이 없는 곳에만 점선 상자 + "계획 업무"(D27). 기록이 있으면 기록이 이긴다. 15분 미만으로 남는 빈 조각에는 그리지 않는다. 계획 대비 실제 비교는 홈 "오늘 지금까지" 막대가 맡는다.

- **블록 누름**: 그 기록의 시트(카테고리·시각 범위·방식). 고치기는 구현 때 기존 기록 시트를 따른다.

### 4.3b 불러오는 중·오류·빈 화면 (2026-11-17, D30~D33)

- **"오늘 지금까지"**: 바닥, [시작] 아래(D37, 사용자 "아래로 옮기는게 낫겠다"). 막대 최대 두 줄. 줄 단위는 목표 줄(세부 항목·항목 없는 집중·운동, 4.3d). 목표가 있는 줄이 셋 이상이면 **진행률(실제 ÷ 계획)이 높은 두 개**(사용자 "많이 진행한 항목 두개"). 같으면 실제 시간이 긴 쪽. 나머지는 시간표·할 일에서 본다. "외 n개"는 쓰지 않는다(D35).
- **작은 화면**: 버튼이 하나라 360×640, 글자 1.3배에서도 버튼 + 두 줄이 바닥에 들어간다. 그래도 다 들어가지 않으면 막대를 통째로 뺀다(D34). 숫자·선반·고양이·버튼은 줄이지 않는다.
- **바닥 묶음 위치(2026-11-21, 사용자 ③ 선택)**: [시작]과 "오늘 지금까지"를 한 묶음(버튼 48 + 간격 22 + 막대 두 줄 약 72)으로 보고 **아래 기준**으로 놓는다. 막대 묶음 끝이 탭 위 20dp에 온다. 바닥선 기준(바닥선 + 22)은 버렸다. 진행 중 [일시정지] [정지]도 [시작]과 같은 높이. 막대가 없을 때(계획 없음 한 줄, 스위치 끔)도 버튼 높이는 바꾸지 않는다. 시안: `~/.gstack/projects/wonseokjee-LEFT30_APP/designs/home-jua-20261118/bottom-pos.html` ③, `home-current.html`.
- **바닥선 아래 빈 곳은 가구·소품 자리(2026-11-21, 사용자 "바닥선 아래는 가구 및 소품으로 채워야해서 크게 비어야 해")**: 바닥선과 바닥 묶음 사이는 UI를 두지 않고 비워 둔다. 키 큰 폰일수록 이 공간이 커지는 것은 의도다. 바닥 가구(캣타워, 스크래처 등, 5.1·8절)와 소품을 놓을 자리이고, 가구가 버튼·막대를 가리지 않게 배치한다(C1). 작은 화면(360×640)에서는 묶음이 바닥선 바로 아래까지 올라오고, 그래도 넘치면 막대를 통째로 뺀다(D34).
- 진행 중에는 막대와 [시작]을 숨기고 [일시정지] [정지]만(D6).
- D36(벽 위쪽으로 올림)은 D37로 되돌렸다.
- **목표가 없을 때(2026-11-18 G19)**: 막대 대신 한 줄 "오늘 계획 없음 ›". 누르면 할 일 탭을 열고 목표 추가 시트를 띄운다(4.3d). 사실만 말하고 재촉하지 않는다. **계정 관리에 "홈에 오늘 지금까지 보이기" 스위치**를 두어 끄면 막대·이 줄을 모두 그리지 않는다(사용자 "설정창에서 홈화면 오늘지금까지 해제 가능하게"). 목표가 있고 실제가 0분이면 "0분 · 계획 2시간" 막대를 그대로 그린다.
- **세부 항목이 0개일 때 시작 시트(G21)**: 칩 줄에 [+ 새 항목] 하나만. 설명 글자는 없다. [시작]은 그대로 누를 수 있다.
- **바닥 위 테두리 버튼(G11)**: [정지]처럼 바닥 위 테두리 버튼은 테두리를 본문색(`#5A4030`, 낮 바닥 5.3:1)으로 그린다. 벽 위·시트 안 테두리는 `#8A705E` 그대로. 시안: `font-20261118/border.html`.
- **홈에 더하지 않는 것(교차 검증, G16)**: 답하지 않은 구간 한 줄("비어 있어요 ›")은 넣지 않는다. 시간표 빈 곳 누름(D29)과 GAP 시트가 맡는다. [지난 30분 기록] 버튼, [집중 시작]으로 이름 바꾸기도 하지 않는다.

### 4.3d 세부 항목별 목표 (2026-11-18, 디자인 리뷰 2, D2~D16)

대상: CEO 리뷰 2 D8(세부 항목별 계획). 저장은 eng 리뷰 2 R7(`plan_v3(local_date, item_id)`). 목표로 둘 수 있는 것: 집중의 세부 항목, 항목 없는 집중(`focus`), 운동. 기타는 두지 않는다. 시안: `~/.gstack/projects/wonseokjee-LEFT30_APP/designs/item-plan-20261118/item-plan.html`(2b, D8, D10, D11, D13이 최종 모양. 1·2·5번의 −/+ 시트 그림은 비교 기록).

```
할 일 탭                                    목표 추가 시트([+ 목표])
11월 18일 (수)                              목표 추가
오늘 목표                       4h          [코딩] [독서] [항목 없는 집중] [운동] [+ 새 항목]
영어                     40m / 1h           코딩        [ 1 ] 시간 [ 30 ] 분
보고서                1h 10m / 2h           [추가]          ← 누르면 줄이 생기고 시트는 열린 채, 그 칩만 빠짐
항목 없는 집중           15m / 1h           구석에 작게 [항목 관리]
운동                       0 / 1h
목표 1개 더 ⌄                               ← 4줄 넘으면 접음
+ 목표
▓▓▓      ▓▓▓|                               ← 하루 막대(그대로)
○ 09:00–10:00 영어                          ← 할 일 블록(그대로)
+ 추가

목표 0개:  오늘 집중할 것과 시간을 정해 보세요
           + 목표    어제와 동일             ← 어제 목표가 있을 때만
```

**자리와 구조**
- **D4 자리**: 목표는 할 일 화면 맨 위의 항목 줄이다. 보이는 곳과 고치는 곳이 같다(사용자 "todo에서 정하는건데 이런 시트가 있어야 하나. 항목 보여주는것은 todo에서 하고 시트에서는 항목을 추가하기만"). 지금 맨 위 한 줄(DR-4 "목표 업무 6h (3h 정함) · 운동 1h ›")과 계획 시트 `PlanTargetSheet`를 이것으로 바꾼다. 아침 계획 제안의 [새로 짜기]와 홈의 "목표 정하기"·"지금 세우기"는 할 일 탭을 열고 추가 시트를 띄운다.
- **D2 집중과 항목**: 숫자는 줄마다 하나(목표)만 고친다. "오늘 목표" 오른쪽 합계는 모든 목표 줄의 합이다. 집중 총량을 따로 적는 칸은 없다.
- **D5 항목 없는 집중**: 추가 시트의 [항목 없는 집중] 칩으로 그 목표 줄을 만든다. 세부 항목 없이 한 집중(알림 [집중], 항목을 비운 타이머)만 여기에 잡힌다. 세부 항목 기록은 이 줄에 잡히지 않아 같은 시간이 두 번 세어지지 않는다. 목표가 없는 항목의 기록은 시간표와 합계에만 나오고 막대는 없다. 나중에 목표를 더하면 그날 이미 한 시간 전체와 비교한다.
- **D6 줄 숫자**: "한 시간 / 목표"(예: `40m / 1h`). 앞은 오늘 기록에서 온 실제(진행 중 타이머 포함, 멈춘 시간 제외). 뒤 목표만 누를 수 있다(점선 밑줄). "정함"(할 일 블록 합)은 보이지 않는다. 블록은 바로 아래 목록에 있다. 홈 막대에 못 오른 항목의 진행도 여기서 본다.
- **D8 순서와 접기**: 추가한 순서대로 고정한다. 항목 없는 집중과 운동은 맨 아래에 둔다. [어제와 동일]로 복사하면 어제 순서를 따른다. 진행률로 순서를 바꾸지 않는다(고치는 도중에 줄이 뛰지 않게). **4줄을 넘으면 4줄 + "목표 n개 더 ⌄"로 접고**(사용자 "나. 4줄 넘으면 접기", 권장 "접지 않음"을 고르지 않음), 누르면 그 자리에서 펼친다. 펼친 상태는 그 화면에 있는 동안 유지한다. 추가하거나 고친 줄이 접힌 쪽에 있으면 펼쳐서 보인다.

**시간 입력**
- **D3 키보드**: 앱이 숫자판을 그리지 않는다. 휴대폰 숫자 키보드(`keyboardType="number-pad"`)를 쓴다(사용자 "폰 자체 패드 없나? 앱에서 만들면 폰마다 비율 달라서" → 근거: React Native TextInput 문서, number-pad는 iOS·Android 공통). −/+ 버튼은 쓰지 않는다(사용자 "버튼은 간단한데 시간 설정은 디테일하게"). 휴대폰 시각 고르기 창은 시각(오후 2:30)용이라 길이에는 쓰지 않는다.
- **D7 규칙**: 목표를 누르면 그 줄이 **시·분 두 칸** `[ 1 ] 시간 [ 15 ] 분`으로 바뀌고, 시간 칸에 키보드가 뜬다. 키보드의 다음 키를 누르면 분 칸(0~59)으로 간다. "2"는 늘 2시간이다. 분을 비우면 0분이다.
  - 저장: 키보드 완료 키를 누르거나 다른 곳을 누르면 저장한다.
  - 취소: 뒤로가기는 취소이고 원래 값으로 돌아간다.
  - 비우기: 두 칸을 비우거나 0으로 저장하면 그 날짜의 목표만 빠진다. 지금 할 일 화면의 [되돌리기] 알림을 띄우고, 항목·기록·블록은 그대로다.
  - 24시간 초과: 하루 합계가 24시간을 넘으면 저장하지 않는다. 친 값을 그대로 두고 2초 알림 "하루 목표는 24시간까지, 2시간 남았어요"를 띄운다(남은 시간은 계산한 값).
  - 키보드가 열리면 고치는 줄과 추가 시트의 [추가]가 키보드 위로 올라온다.
  - 저장 실패: 원래 값으로 되돌리고 D31의 2초 알림을 띄운다.

**추가와 항목 관리**
- **D10 추가 시트**:
  - 칩: 오늘 목표가 없는 최근 항목 칩(최근 사용순, R7 최근 칩) + [항목 없는 집중] + [운동] + [+ 새 항목].
  - 칩을 고르면 시·분 두 칸의 시간 칸에 키보드가 뜬다.
  - [추가]를 누르면 할 일 화면에 줄이 생기고, **시트는 열린 채로 그 칩만 빠진다.** 닫기는 아래로 끌기나 뒤로가기다.
  - 최근 항목이 없으면 그 칩 묶음을 비워 두지 않고 생략한다.
- **D12 이름 바꾸기·숨기기**(사용자 "1,3 둘다 가능하게"): 두 길을 둔다.
  - ① 칩(시작·기록·추가 시트)이나 목표 줄을 길게 누르면 작은 메뉴 [이름 바꾸기] [숨기기]가 뜬다.
  - ② 추가 시트 구석의 작은 [항목 관리]에서 목록으로 이름 바꾸기·숨기기를 하고, 숨긴 항목은 거기서 다시 꺼낸다.
  - 숨기면 최근 칩에서만 빠진다. 오늘 목표·옛 기록·블록은 그대로다.
  - 이름을 바꾸면 옛 기록에도 새 이름이 보인다(항목 하나, R7).
  - 기본 항목(집중·운동·기타)은 길게 눌러도 메뉴가 없다.
- **D13 이름**: 최대 10자(입력 칸에 `9/10`). 앞뒤 빈칸은 지우고 비교한다. 이미 있는 이름(숨긴 것 포함)이면 새로 만들지 않고 그 항목을 고르며, 숨김도 푼다. 이때 한 줄로 "이미 있는 항목이에요. 영어를 골랐어요"라고 알린다. 홈 막대(한글 4~5자)와 시간표 블록에서 넘치면 말줄임한다.
- **D14 운동**: 한 줄이고 세부 항목은 없다. [+ 새 항목]은 늘 집중 아래에 만든다. 테스터가 요청하면 연다(R7은 이미 받을 수 있음).

**빈 화면·흐름·홈**
- **D9 목표 0개**: "오늘 목표" 제목과 합계를 숨긴다. 안내 한 줄 "오늘 집중할 것과 시간을 정해 보세요"와 [+ 목표]를 둔다(사용자 "나. 안내 한 줄 + [+ 목표]", 권장 "한 줄만"을 고르지 않음). 목표가 하나라도 생기면 안내는 사라진다. 불러오는 중·오류는 D30~D32를 그대로 따른다(그 자리 한 줄 + [다시 시도], 1초 뒤 뼈대).
- **D11 어제와 동일**: 오늘 목표가 0개이고 새 구조의 어제 목표가 있을 때만 [+ 목표] 옆에 [어제와 동일]을 둔다. 누르면 어제 목표를 같은 순서로 복사한다. 아침 계획 제안(15시 전 첫 진입)은 그대로 있다.
- **D16 홈 막대 이름**: 홈 "오늘 지금까지"(4.3c)의 줄은 목표 줄(세부 항목·항목 없는 집중·운동) 가운데 진행률이 높은 두 개다. 항목 없는 집중은 홈에서 **"집중"**이라고 짧게 쓰고, 화면 읽기는 "항목 없는 집중"으로 읽는다.
- 시간표 점선 계획 상자(D27)의 이름은 할 일 블록의 항목 이름이다("계획 영어").

**화면 읽기와 큰 글자(D15, 2.3을 따름)**
- 목표 줄은 "영어, 40분 함, 목표 1시간, 두 번 눌러 목표 수정"으로 읽는다. 누르는 자리는 줄 오른쪽 절반 전체(48dp 이상)다.
- 입력 칸은 "목표 시간, 시간" / "목표 시간, 분"으로 읽는다. 저장하면 "1시간 15분으로 저장"을 알린다. 빠짐·24시간 초과·같은 이름은 알림 문구를 그대로 읽는다.
- "목표 n개 더"는 "목표 n개 더 보기, 버튼"으로 읽는다. 홈의 "집중" 줄은 "항목 없는 집중, …"으로 읽는다.
- 글자 1.3배에서는 줄이 높아지고 "한 시간 / 목표"는 한 줄을 지킨다. 이름은 말줄임한다.

### 5.0 에셋 제작 규칙 (2026-11-17, 사용자)

정본은 design/cat-image의 `docs/designs/ASSET_DESIGN_RULES.md`(버전 기록은 `room/README.md`). 요약:

- **순서**: 밝은 세로 Home 방의 가구·소품과 배치를 먼저 정한다. 밤 버전은 밝은 버전이 정해진 뒤 마지막에 만든다. 가로는 지금 범위가 아니다(4.2).
- **레이어**: 새 에셋은 배경·고양이·타이머·문구를 합치지 않은 독립 투명 레이어. 아크릴처럼 비치는 부분은 실제로 투명해야 한다. 바닥에 닿는 물체는 보이는 아래 끝을 벽·바닥 경계(63%)에 맞추고, 캣타워 같은 높은 가구는 별도 레이어.
- **선 굵기**: 모든 신규·수정 에셋의 바깥선과 내부선(윗면·앞면 경계, 이음선, 박음질, 아크릴 테두리)은 기준 고양이 `cat/calico_cat_tail_up.png`의 선과 **최종 화면 표시 크기에서 같은 굵기**로 보이게 한다. 원본 픽셀이 아니라 고양이와 나란히 놓은 실제 크기 미리보기로 확인한다. 어두운 앞면 전체가 굵은 선처럼 보이는지도 본다.
- **선 색**: 각 에셋의 재질 색(목재·천·아크릴)을 따른다. 고양이 털색·품종 선 색을 가구에 복사하지 않는다(P1).
- **표면**: 매끈한 무광 + 아주 약한 질감(P4).
- **접점**: 고양이가 앉거나 착지하는 자리, 발·가구 접점, 가림 순서, anchor를 실제 화면 크기에서 확인한다. 접점에는 짧고 부드러운 그림자만.
- **투명 가장자리 정리:** 일부 그림(`calico_cat_tail_up.png`, `calico_cat_loaf.png`, `calico_cat_peek.png`, `calico_cat_sleep.png`)의 가장자리에 빨강·노랑 점이 남아 있다. 어두운 바탕에서 잘 보인다. 앱용으로 줄일 때 정리한다.
- `cat/image_1~3.png`는 출처를 확인하기 전까지 커밋하지 않는다. 워터마크가 있는 스톡 이미지는 저장소에 넣지 않는다.

## 8. 사료와 가구 (나중 단계)

### 8.1 흐름

1. 기록하면 사료를 받는다.
2. 사료로 가구(캣타워, 해먹 등)를 산다.
3. 산 가구를 Home 방에 놓는다. 고양이가 앉는 자리가 바뀐다.

### 8.2 사료를 주는 기준 (결정: 기록 칸 수)

"일정 시간 이상 사용"을 **앱을 켜 둔 시간이 아니라 기록한 칸 수**로 세기를 권한다.
- 이 앱은 앱을 오래 보지 않게 하는 것이 목표라, 화면 시간에 보상하면 방향이 반대가 된다.
- 기록 칸 수는 이미 S1-COUNT(하루 응답한 30분 구간 수)로 세고 있어 새 계산이 필요 없다. 타이머 개편으로 기록이 시각 구간이 되면 "기록한 칸"의 정의를 다시 맞춘다.
- 예: 하루에 응답한 칸 3개마다 사료 1개, 하루 최대 N개. 몰아 채우기(batch)로 채운 칸을 같은 값으로 셀지는 정한다.

### 8.3 출시 시기 (결정: 2주 검증 뒤)

사료와 가구는 보상 장치라서, 스트릭(E4)을 연기한 것과 같은 이유가 생긴다. 2주 테스터 검증이 "계획 대비 실제 피드백의 효과"를 보려는 것인데, 보상이 섞이면 무엇이 효과를 냈는지 구분하기 어렵다.
**권장: 고양이 그림과 상태 모션은 먼저 넣고, 사료와 가구는 2주 검증이 끝난 뒤 넣는다.**

### 8.4 데이터

- 사료는 잔액을 따로 저장하지 않고 이벤트로 남긴다: `feed_earned {amount, local_date, reason}`, `item_bought {item_id, price}`, `item_placed {item_id, slot}`.
- 잔액과 보유 가구는 이벤트를 합쳐 계산한다. 이벤트는 이미 서버와 동기화되므로 서버에 새 엔티티가 필요 없다. 재설치해도 복원된다.
- 같은 날 사료가 두 번 지급되지 않도록 `feed_earned` id를 결정적으로 만든다(`uuidv5(user|feed|local_date|n)`, 핑 이벤트와 같은 방식).
- 가구 목록과 가격은 앱 안 상수(카탈로그)로 둔다.

## 9. 확장 구조

모션, 가구, 화면을 코드 수정 없이(또는 최소로) 늘리기 위해 네 가지를 데이터로 정의한다.

```
Motion  고양이 동작 한 개      (sit, groom, walk, climb_down …)
Spot    고양이가 머무는 자리    (floor, tower_top, tower_mid, hammock, digit_top …)
Item    가구                    (자리 목록, 그림 레이어, 가로 잘라내기 영역, 가격)
Rule    상태 → 행동 순서 고르기  (트리거, 후보 순서, 가중치, 쿨다운)
```
타이머 숫자 구조물(P6)도 자리(Spot)를 가진 기본 가구 하나로 다루면, 고양이가 숫자 위로 오르내리는 모션을 같은 구조로 넣을 수 있다.

### 9.1 Motion

```ts
type Motion = {
  id: string;              // 'groom'
  frames: ImageSource[];   // 또는 renderer별 리소스
  fps: number;
  loop: boolean;
  anchor: { x: number; y: number }; // 원본 그림 안 기준점, 0~1. 선 포즈는 발 닿는 점, 공중·빼꼼 포즈는 전환 기준점
  scale: number;           // tail_up 대비 표시 배율. 머리·몸통 크기로 맞춘 값(5절)
  moves?: 'walk' | 'jump' | 'climb'; // 자리 이동 모션이면 이동 방식
};
```
- 포즈마다 원본 캔버스 크기가 달라도 된다. 원본은 고치지 않고 `scale`·`anchor`로 맞춘다. 한 모션 안의 프레임끼리는 같은 캔버스·기준점으로 만든다.
- 낮/밤에서 같은 포즈는 `scale`·`anchor`가 같다. 가로·세로 비율은 바꾸지 않는다.
- 파일: `assets/cat/<품종>/<motion>/<번호>.webp`.

### 9.2 Spot과 Item

```ts
type Spot = { id: string; x: number; y: number; scale: number; poses: string[] }; // 장면 좌표 0~1
type Item = {
  id: string;              // 'tower_basic'
  price: number;
  layers: { back: ImageSource; front?: ImageSource }; // front가 고양이를 가리는 부분(해먹 천, 상자 앞면 등)
  spots: Spot[];
  landscape: { crop: Rect; spot: string };            // 가로에서 보일 영역과 앉을 자리
};
```
- 그림은 뒤 레이어, 고양이, 앞 레이어 순으로 겹친다. 해먹이나 상자 안에 들어간 모습을 그림 하나로 만들 필요가 없다.

### 9.3 Rule과 감독(Director)

```ts
type Trigger = 'idle' | 'focus' | 'quiet' | 'recorded' | 'checked' | 'empty'
             | 'rotate' | 'enter_todo' | 'enter_timetable' | 'fed';
type Rule = {
  trigger: Trigger;
  scene: 'home' | 'home_land' | 'strip';
  steps: Array<{ motion: string; spot?: string; ms?: number }>; // 예: walk_in → sit → groom
  weight: number;
  cooldownMs?: number;
};
```
- 감독은 순수 함수다: `pickBehavior(trigger, scene, placedItems, history, rand) → steps`. 다른 로직(`record/`, `scheduler/`)처럼 jest로 테스트한다.
- 화면 컴포넌트 `<CatStage scene=… />`는 감독이 준 순서를 재생만 한다.
- 새 모션 추가는 "그림 넣기 + Motion 한 줄 + Rule 한 줄"로 끝나야 한다.
- 트리거는 타이머 개편 상태(스톱워치, 뽀모도로 집중·휴식, 일시정지)에 맞춰 늘린다(3절).

### 9.4 재생 방식 (의존성)

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. PNG 프레임 + RN `Animated` (권장 시작안) | 프레임 넘기기, 위치 이동만 `Animated` | 의존성 없음, 손그림 애니 느낌과 잘 맞음 | 프레임이 많으면 용량 증가 |
| B. Lottie | 벡터 애니메이션 파일 | 부드럽고 가벼움 | `lottie-react-native` 추가, 제작 도구 필요 |
| C. Rive | 상태 머신이 들어간 캐릭터 파일 | 상태 전환·상호작용에 가장 강함 | `rive-react-native` 네이티브 모듈 추가, 학습 비용 |

- A로 시작하고, `CatStage` 안의 재생부만 바꾸면 B나 C로 옮길 수 있게 인터페이스를 둔다.
- 이미지 생성 도구는 정지 포즈에는 강하지만 **같은 고양이의 연속 프레임**은 흔들리기 쉽다. 모션은 핵심 프레임 2~4장으로 시작하고, 부드러운 동작이 필요해지면 C를 검토한다.
