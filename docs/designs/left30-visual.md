# LEFT30 화면 디자인: 고양이와 수채화

작성 2026-11-12(고양이), 2026-11-16(수채화). 2026-11-16 두 문서(`left30-cat.md`, `left30-watercolor.md`, design/cat·design/cat-image 브랜치)를 이 문서 하나로 합쳐 refactor/architecture로 옮겼다. 그 브랜치의 옛 문서는 이 문서를 가리키는 안내만 남긴다.
상태: **원칙·홈 배치·글자 색·시간표 모양 확정(2026-11-17), 강조색 최종값·글꼴 미정.** 방 배경(낮·밤)과 가구 3종을 받았다(design/cat-image `docs/designs/room/`). 고양이 0단계(역할과 구조) 확정, 1단계(스타일)는 수채화로 정함.
관련: 기능과 데이터 `left30-timer-modes.md`(타이머 개편, 디자인 리뷰 진행 상태와 배경 그림 요청 조건), 재출시 설계 `left30-relaunch.md`(D4 기록 1탭, D7·D12~D15 디자인 리뷰, D10 사실만 쓰기, E4 스트릭 연기), 집중 블록 `left30-focus-block.md`, 현재 화면 점검 `current-app-design-audit.md`.

**그림 원본 위치:** 고양이 그림 원본과 품종별 재생성 규칙(`cat/*.png`, `cat/*-regeneration-guide.md`)은 용량 때문에 **design/cat-image 브랜치의 `docs/designs/cat/`에만 둔다**(커밋 안 된 파일 포함). 이 브랜치에는 앱에 넣을 때 줄인 파일(`application/assets/cat/`)만 들어온다. 이 문서에서 `cat/…`는 그 위치를 뜻한다.

## 1. 목표

- 앱의 얼굴을 고양이로 바꾼다. 고양이는 Home에 늘 있고, 앱 상태에 따라 행동이 바뀐다.
- 고양이와 가구는 동화책 수채화, 바탕과 UI는 단색 + 옅은 종이결이다(P4). **홈은 고양이가 사는 방 그림이 된다**(P6).
- 나중에 모션, 가구, 화면을 계속 늘릴 수 있도록 처음부터 **데이터로 정의하고 코드는 재생만 하는 구조**로 만든다(9절).

## 2. 원칙

### 2.1 화면 (2026-11-16, 사용자)

| # | 원칙 | 근거 |
|---|---|---|
| P1 | **품종 중립.** 고양이는 삼색(calico) 외에 검정·흰색·회색·크림 등 여러 품종을 쓴다. 털색은 그 품종 그림에만 속하고, 앱의 버튼·카테고리·가구 기본색으로 가져오지 않는다. 품종마다 화면 테마를 바꾸지 않는다 | 사용자 지시 "calico만 기준으로 색을 잡으면 안 돼" |
| P2 | **색 축약.** UI는 중립색(바탕·표면·글자·선)과 강조색 하나로 만든다. 경고·삭제에도 상시 색을 더하지 않고 문구와 확인 동작으로 표현한다 | 사용자 지시 "색이 너무 많으면 복잡해 보여" |

| P5 | **행동 원칙 유지.** 카드·테두리·그림자 없음(D12), 기록 1탭(D4), 사실만 쓰기(D10), 접근성(D15). 화면 모양은 P6·P7로 새로 만든다 | 2026-11-16 "기존을 완전히 갈아 엎을거야"로 화면 구성은 새로 하고, 1탭·사실만·접근성은 바꾸라는 말이 없어 유지로 본다 |
| P6 | **홈 배경은 고양이 방.** 타이머 숫자는 방 안의 구조물이 되고, 나중에 고양이가 그 위로 오르내리는 모션을 넣는다(모션은 나중) | 2026-11-16 사용자 "홈 배경화면은 고양이 방이 되어야해. 타이머 숫자가 구조물이 되어서 그 위로 고양이가 올라가는 등의 모션도 계획중이야. 이건 나중에" |

색은 여전히 줄인다(P2). 방 그림은 고양이보다 채도·대비를 낮춰 고양이가 앞에 보이게 한다.

### 2.3 접근성 (2026-11-17, 디자인 리뷰 D19)

- 누르는 곳은 48dp 이상.
- 큰 숫자는 폰 글자 크기 설정을 1.3배까지만 따른다(화면 넘침 방지). 다른 글자는 그대로 따른다.
- 화면 읽기: 숫자는 초마다 읽지 않는다. 숫자에 붙는 말은 짧게 "1시간 23분 지남", "18분 남음"(분 단위). "공부 · 스톱워치"는 아래 라벨이 따로 읽힌다.
- 움직임 줄이기: 앱 설정을 따로 만들지 않고 폰의 "애니메이션 제거"를 따른다(C4). 고양이 모션과 숫자 바뀜 애니메이션을 끈다.
- 상태는 흐림·색만이 아니라 글자로도 보인다(예: "일시정지 중").

### 2.4 다크 모드 (2026-11-17, D15)

- 기본은 폰 설정을 따르고, 계정 관리에 "화면: 폰 설정 / 낮 / 밤" 한 줄을 둔다.

### 2.2 고양이 (2026-11-12)

- **C1 기록과 타이머를 가리지 않는다.** 고양이는 터치를 받지 않는다(`pointerEvents='none'`). 기록 1탭, 타이머, 시간표 칸 위로 올라오지 않는다.
- **C2 고양이는 평가하지 않는다.** 기록을 놓쳐도 슬퍼하거나 화내지 않는다. D10(사실만, 평가 없음)과 같은 원칙이다. 기록했을 때 반기는 반응은 괜찮다.
- **C3 표시는 적게.** Home 밖 화면(Todo, Timetable)에는 가끔만 나온다.
- **C4 움직임 줄이기 설정을 따른다.** OS의 "애니메이션 제거"가 켜져 있으면 정지 포즈만 보여 준다.
- **C5 배터리.** 앱이 백그라운드이거나 화면이 안 보이면 재생을 멈춘다. 반복 모션은 쉬는 간격을 둔다.

## 4. 화면별 장면

탭 순서는 `Todo | Home | Timetable`이다.

### 4.1 Home 세로

- **방이 화면 전체 배경이다(P6).** 처음 안(화면 아래쪽 또는 타이머 옆의 "방" 영역)은 버렸다.
- 타이머 숫자는 방 안의 구조물이다. **배치는 벽 선반으로 정함(2026-11-17, D22).** 숫자는 벽에 걸린 선반(`floating-shelf-light-v1.png`) 위의 물건처럼 서고, 고양이는 선반 끝에 앉는다. 숫자 위 작은 글자 "다음 알림까지". 바닥(바닥선 약 63% 아래)에 세 버튼과 "오늘 지금까지". 진행 중에는 선반 아래에 "공부 · 스톱워치 · 30분 알림 쉼" 라벨, 바닥에 [일시정지] [정지]만 남는다. 나중에 고양이가 선반에서 숫자 위로 오르는 모션이 이어진다. 시안: `~/.gstack/projects/wonseokjee-LEFT30_APP/designs/home-timer-20261116/home-real-bg.html` ①.
- 책상·스툴은 홈 기본 배치에 쓰지 않고 사료·가구 단계(8절)의 가구 후보로 둔다.
- 처음에는 가구 없이 바닥(또는 숫자 구조물)에 앉아 있다. 가구를 놓으면 그 가구의 **자리**에 앉는다(예: 캣타워 맨 위, 해먹 안).
- 가구가 여러 개면 고양이가 가끔 자리를 옮긴다(걷기, 점프, 내려오기 모션).

### 4.2 Home 가로

- 가로 화면은 높이가 낮아 캣타워 전체를 그리지 않는다. 가구마다 정해 둔 **가로용 잘라내기 영역**(보통 가운데 부분)만 보여 준다.
- 회전하면 고양이가 위 자리에서 가운데 자리로 **내려와 앉는 모션**을 한 번 재생한다. 세로로 돌아오면 반대로 올라간다.
- 가구가 없으면 바닥에 앉은 고양이만 작게 보인다.

### 4.3 Todo, Timetable

- 탭 바 바로 위, 화면 맨 아래의 얇은 띠(높이 약 56dp)에만 나온다. 목록과 시간표의 아래 여백을 그만큼 늘려 내용을 가리지 않게 한다.
- **Home이 있는 쪽에서 걸어 들어온다.** Todo는 Home의 왼쪽 탭이라 오른쪽 끝에서 들어오고, Timetable은 오른쪽 탭이라 왼쪽 끝에서 들어온다. 탭을 넘어 따라온 느낌을 준다.
- 들어와서 앉은 뒤 그루밍, 하품, 꼬리 흔들기 중 하나를 하고, 잠시 뒤 다시 걸어 나가거나 그대로 앉아 있는다.
- 매번 나오지 않는다. 예: 그 화면에 들어올 때 30% 확률, 같은 화면은 10분에 한 번까지. 수치는 시안을 보고 정한다.

### 4.3a 시간표 = 구간 타임라인 (2026-11-17, D26~D29)

시안: `~/.gstack/projects/wonseokjee-LEFT30_APP/designs/home-timer-20261116/timetable.html`. 기록이 30분 칸에서 시작~끝 구간으로 바뀐 데 따른 모양이다(타이머 개편 TIMELINE).

- **열**: 어제·오늘 두 열을 유지한다(D26). 열이 좁으므로 블록 안에는 이름만 쓰고, 시각 범위·방식(타이머·뽀모도로·스톱워치)은 블록을 누르면 나오는 시트에서 보인다.
- **크기**: 1분 = 1.1dp(30분 = 33dp, 지금 28dp에서 조금 키움). 시각 표시는 정시마다, 정시 가는 가로줄.
- **블록**: 카테고리 색 없이 모두 같은 채움(낮 `#E0CCB7`, 밤 `#57504A`) + 왼쪽 3dp 강조선. 이름은 블록 위쪽. 서로 다른 기록 사이는 2dp 틈. 30분 알림 답이 같은 카테고리로 이어지면 한 덩어리로 그린다. 같은 카테고리라도 기록 출처가 다르면(알림 답 → 타이머) 따로 그린다.
- **짧은 블록**: 15분 미만은 이름 없이 블록만 그린다(D28). 누르면 시트에서 보이고, 화면 읽기는 항상 이름을 읽는다.
- **멈춤·휴식**: 5분 미만 멈춤과 뽀모도로 휴식은 블록 안에 약간 옅은 색(낮 `#E9D9C7`, 밤 `#48423E`)으로 칠한다(D13). 5분 이상 멈춤은 빈 틈으로 두고 앞뒤 조각을 점선으로 잇는다. 뒤 조각에는 이름을 반복하지 않는다(타이머 개편 PAUSE).
- **진행 중**: 지금 선까지 자라고 아래 끝이 흐려진다. 이름 뒤에 "진행 중".
- **지금 선**: 강조색 가로선, 왼쪽 시각 칸에 지금 시각.
- **계획**: 기록이 없는 곳에만 점선 상자 + "계획 업무"(D27). 기록이 있으면 기록이 이긴다. 15분 미만으로 남는 빈 조각에는 그리지 않는다. 계획 대비 실제 비교는 홈 "오늘 지금까지" 막대가 맡는다.
- **빈 곳 누름**: 지난 빈 곳을 누르면 먼저 시작·끝을 고르는 화면이 열린다(D29). 처음 값은 누른 빈 구간 전체(예: 15:00–15:43)이고, 사용자가 줄이거나 옮긴 뒤 카테고리를 고른다. 다른 기록과 겹치게는 고를 수 없다.
- **블록 누름**: 그 기록의 시트(카테고리·시각 범위·방식). 고치기는 구현 때 기존 기록 시트를 따른다.

### 4.3b 불러오는 중·오류·빈 화면 (2026-11-17, D30~D33)

시안: `~/.gstack/projects/wonseokjee-LEFT30_APP/designs/home-timer-20261116/states-error.html`. 기록은 폰 안(SQLite)에 있어 읽기는 대개 0.1초 안에 끝난다. 지금 코드는 실패를 `console.warn`에만 남겨 화면이 비거나 버튼이 반응 없이 끝난다.

- **읽기 실패**(시간표, 홈 "오늘 지금까지", 할 일): 실패한 그 자리에 한 줄 + [다시 시도](D30). 예: "시간표를 불러오지 못했어요 / 기록은 지워지지 않았어요". 홈은 막대 자리만 "불러오지 못했어요 · 다시 시도"로 바뀌고 숫자·버튼·고양이는 그대로.
- **버튼 실패**(정지, 저장, 시작, 일시정지·재개): 화면은 누르기 전 상태 그대로 두고 아래에 짧은 알림 **2초**(D31, 사용자 "4초는 길다 2초"). 예: "정지하지 못했어요. 다시 눌러 주세요". "정지 취소" 알림과 같은 자리·모양. 화면 읽기가 알림을 읽는다.
- **불러오는 중**: 아무것도 그리지 않는다. 1초가 넘을 때만 블록 모양의 옅은 뼈대(D32).
- **기록이 없을 때**: 시간표는 아무 문구 없이 빈 시간표 그대로(D33). 빈 상태 하품 그림(5.1)은 시간표에 쓰지 않는다.
- **동기화 실패**: 화면에 보이지 않는다. 큐에 남아 다시 시도한다(지금 코드 그대로). 1단계는 구간 동기화를 끈다(타이머 개편 SYNC).
- 앱 시작 때 로컬 DB 이전 실패는 기존 `BootError` 화면("업데이트 중 문제가 생겼어요")을 그대로 쓴다.

## 8. 사료와 가구 (나중 단계)

### 8.1 흐름

1. 기록하면 사료를 받는다.
2. 사료로 가구(캣타워, 해먹 등)를 산다.
3. 산 가구를 Home 방에 놓는다. 고양이가 앉는 자리가 바뀐다.

### 8.2 사료를 주는 기준 (결정: 기록 칸 수)

"일정 시간 이상 사용"을 **앱을 켜 둔 시간이 아니라 기록한 칸 수**로 세기를 권한다.
- 이 앱은 앱을 오래 보지 않게 하는 것이 목표라, 화면 시간에 보상하면 방향이 반대가 된다.
- 기록 칸 수는 이미 S1-COUNT(하루 응답한 30분 구간 수)로 세고 있어 새 계산이 필요 없다. 타이머 개편으로 기록이 시각 구간이 되면 "기록한 칸"의 정의를 다시 맞춘다.
- 예: 하루에 응답한 칸 3개마다 사료 1개, 하루 최대 N개. 몰아 채우기(batch)로 채운 칸을 같은 값으로 셀지는 정한다.

### 8.3 출시 시기 (결정: 2주 검증 뒤)

사료와 가구는 보상 장치라서, 스트릭(E4)을 연기한 것과 같은 이유가 생긴다. 2주 테스터 검증이 "계획 대비 실제 피드백의 효과"를 보려는 것인데, 보상이 섞이면 무엇이 효과를 냈는지 구분하기 어렵다.
**권장: 고양이 그림과 상태 모션은 먼저 넣고, 사료와 가구는 2주 검증이 끝난 뒤 넣는다.**

### 8.4 데이터

- 사료는 잔액을 따로 저장하지 않고 이벤트로 남긴다: `feed_earned {amount, local_date, reason}`, `item_bought {item_id, price}`, `item_placed {item_id, slot}`.
- 잔액과 보유 가구는 이벤트를 합쳐 계산한다. 이벤트는 이미 서버와 동기화되므로 서버에 새 엔티티가 필요 없다. 재설치해도 복원된다.
- 같은 날 사료가 두 번 지급되지 않도록 `feed_earned` id를 결정적으로 만든다(`uuidv5(user|feed|local_date|n)`, 핑 이벤트와 같은 방식).
- 가구 목록과 가격은 앱 안 상수(카탈로그)로 둔다.

## 9. 확장 구조

모션, 가구, 화면을 코드 수정 없이(또는 최소로) 늘리기 위해 네 가지를 데이터로 정의한다.

```
Motion  고양이 동작 한 개      (sit, groom, walk, climb_down …)
Spot    고양이가 머무는 자리    (floor, tower_top, tower_mid, hammock, digit_top …)
Item    가구                    (자리 목록, 그림 레이어, 가로 잘라내기 영역, 가격)
Rule    상태 → 행동 순서 고르기  (트리거, 후보 순서, 가중치, 쿨다운)
```
타이머 숫자 구조물(P6)도 자리(Spot)를 가진 기본 가구 하나로 다루면, 고양이가 숫자 위로 오르내리는 모션을 같은 구조로 넣을 수 있다.

### 9.1 Motion

```ts
type Motion = {
  id: string;              // 'groom'
  frames: ImageSource[];   // 또는 renderer별 리소스
  fps: number;
  loop: boolean;
  anchor: { x: number; y: number }; // 발 아래 가운데, 0~1
  moves?: 'walk' | 'jump' | 'climb'; // 자리 이동 모션이면 이동 방식
};
```
- 모든 프레임은 같은 캔버스 크기, 같은 기준점(발 아래 가운데)으로 만든다. 그래야 자리만 바꿔 끼워도 어긋나지 않는다.
- 파일: `assets/cat/<품종>/<motion>/<번호>.webp`.

### 9.2 Spot과 Item

```ts
type Spot = { id: string; x: number; y: number; scale: number; poses: string[] }; // 장면 좌표 0~1
type Item = {
  id: string;              // 'tower_basic'
  price: number;
  layers: { back: ImageSource; front?: ImageSource }; // front가 고양이를 가리는 부분(해먹 천, 상자 앞면 등)
  spots: Spot[];
  landscape: { crop: Rect; spot: string };            // 가로에서 보일 영역과 앉을 자리
};
```
- 그림은 뒤 레이어, 고양이, 앞 레이어 순으로 겹친다. 해먹이나 상자 안에 들어간 모습을 그림 하나로 만들 필요가 없다.

### 9.3 Rule과 감독(Director)

```ts
type Trigger = 'idle' | 'focus' | 'quiet' | 'recorded' | 'checked' | 'empty'
             | 'rotate' | 'enter_todo' | 'enter_timetable' | 'fed';
type Rule = {
  trigger: Trigger;
  scene: 'home' | 'home_land' | 'strip';
  steps: Array<{ motion: string; spot?: string; ms?: number }>; // 예: walk_in → sit → groom
  weight: number;
  cooldownMs?: number;
};
```
- 감독은 순수 함수다: `pickBehavior(trigger, scene, placedItems, history, rand) → steps`. 다른 로직(`record/`, `scheduler/`)처럼 jest로 테스트한다.
- 화면 컴포넌트 `<CatStage scene=… />`는 감독이 준 순서를 재생만 한다.
- 새 모션 추가는 "그림 넣기 + Motion 한 줄 + Rule 한 줄"로 끝나야 한다.
- 트리거는 타이머 개편 상태(스톱워치, 뽀모도로 집중·휴식, 일시정지)에 맞춰 늘린다(3절).

### 9.4 재생 방식 (의존성)

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. PNG 프레임 + RN `Animated` (권장 시작안) | 프레임 넘기기, 위치 이동만 `Animated` | 의존성 없음, 손그림 애니 느낌과 잘 맞음 | 프레임이 많으면 용량 증가 |
| B. Lottie | 벡터 애니메이션 파일 | 부드럽고 가벼움 | `lottie-react-native` 추가, 제작 도구 필요 |
| C. Rive | 상태 머신이 들어간 캐릭터 파일 | 상태 전환·상호작용에 가장 강함 | `rive-react-native` 네이티브 모듈 추가, 학습 비용 |

- A로 시작하고, `CatStage` 안의 재생부만 바꾸면 B나 C로 옮길 수 있게 인터페이스를 둔다.
- 이미지 생성 도구는 정지 포즈에는 강하지만 **같은 고양이의 연속 프레임**은 흔들리기 쉽다. 모션은 핵심 프레임 2~4장으로 시작하고, 부드러운 동작이 필요해지면 C를 검토한다.
